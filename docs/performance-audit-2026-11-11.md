# Аудит производительности и новой админки — 11 ноября 2026

## Результат

У главной устранена автоматическая загрузка тяжёлой карты, уменьшены скачки разметки и затраты на прокрутку. Сохранены программа, 13 спикеров, 8 номинаций и 79 кандидатов. Публичные формы пока закрыты по отдельной договорённости.

## Методика и ограничения

Сравнивались неизменённая копия `site/` до оптимизации и исправленная версия на отдельном локальном Nginx/Gunicorn-стенде. Исходная рабочая база и старые Docker-контейнеры не изменялись.

Chromium запускается в отдельных контейнерах с реальными ограничениями `--memory` 512 МБ / 1 ГБ / 2 ГБ, без swap и с одной CPU. Дополнительно применяется замедление CPU в DevTools; мобильные профили получают задержку сети 80–300 мс и пропускную способность 100–500 КБ/с. Кэш отключён. Память включает весь контейнер браузера и измеряется через cgroup `memory.peak`.

Это эмуляция экранов и ресурсов, а не испытания на физических Android/iPad. Лимит контейнера не моделирует все особенности мобильной ОС и GPU. Результаты — лабораторные прогоны на этом Mac, а не гарантия времени для любого устройства или сети. Прокрутка измеряется за 4 секунды; FPS в таблице — число полученных кадров / 4. Пик памяти ниже показан для первой страницы профиля; последующие значения в JSON могут включать накопленный пик контейнера.

## Изменения

1. Карты Яндекса на главной и ESG загружаются только по явному нажатию «Показать интерактивную карту». Адрес и ссылка на маршрут доступны сразу.
2. Onest и Montserrat размещены локально в WOFF2 с кириллицей и лицензиями OFL. Внешних запросов к Google Fonts больше нет; поздняя загрузка шрифта не перестраивает страницу.
3. Для фона подготовлены WebP 640/1280/1920 px; портреты получают 320/640 px и `srcset`. Зарезервированы размеры статических изображений.
4. Убраны фиксированный фон длинной витрины и тяжёлое размытие при прокрутке.
5. Первая карточка форума заранее присутствует в HTML. Обратный отсчёт изменяет только изменившиеся значения, останавливается в скрытой вкладке; программа запрашивается главной только во время проведения форума.
6. Зарезервировано место для результатов загрузки конкурса. Итоговый CLS этой страницы на всех шести профилях меньше 0,1.
7. Nginx сжимает HTML/CSS/JS/JSON/SVG. Статические ресурсы кэшируются, CSS/JS получают версию по содержимому; HTML перепроверяется. Это не распространяется на личные билеты и API.
8. Программа: 48 → 11 SQL-запросов; конкурс: 10 → 3. JSON сравнен с исходным ответом целиком. Добавлены проверки ограничения числа запросов и отсутствия скрытого контента.

## Проверки браузеров и интерфейса

Сырые JSON, скриншоты и проверочные сценарии находятся в `docs/performance-results/` и `tools/performance/`. Chromium и WebKit прошли по 15 сценариев: главная, промтур и конкурс на ширинах 320/360/768/1024/1440, открытие карты по нажатию, карточка спикера, закрытие диалога, 79 кандидатов и закрытые формы. Внешних запросов до открытия карты нет.

Отдельно выполнена прокрутка в настоящем Chrome на этом Mac с 16 ГБ RAM без искусственного замедления (`native-mac.json`): 189 → 242 кадра за 4 секунды; кадров длиннее 50 мс — 4 → 0.

Все 15 автоматических Django-тестов прошли: права руководителя и ролей, вход с отключённым TOTP, защита руководителя от удаления, создание рабочего аккаунта сотрудника, ошибки капчи и границы публичного каталога.

Проверены парольный вход созданного сотрудника и отказ в создании аккаунтов для него. Кнопки одобрения/отклонения в карточке заявки используют основной workflow, создают запись истории и ставят уведомление в очередь; прямое редактирование статуса отключено.

Новая админка: русские названия моделей, полей и прав; навигация по рабочим задачам; счётчики заявок/модерации; доступ к регистрации на месте и выгрузкам; создание сотрудника с ролью за один шаг. Справочники, формы и массовые действия остаются доступны. Проверки интерфейса и создания сотрудника выполняются только в локальной тестовой базе.

## Доступ и права

Единственный руководитель — `director`. Его пароль изменён, старые сессии аннулированы; пароль хранится вне исходников. TOTP временно отключён по прямому запросу владельца через `ADMIN_TOTP_REQUIRED=0`. Включение обратно — значение `1`.

Только руководитель может создавать/менять/удалять пользователей и группы, сбрасывать TOTP других сотрудников. Это проверяется и для другого superuser. Доступ ролей к выгрузкам и служебным API проверяется на сервере. Руководитель защищён от удаления и случайного отключения.

## Воспроизведение

```sh
# До изменения site/ сохраните отдельную копию для сравнения.
export AUDIT_BASELINE_DIR=/absolute/path/to/baseline-site
npm run build
docker compose -f deploy/docker-compose.audit.yml up -d --wait
docker build -t sibforum-perf-runner:1.63.0 tools/performance
bash tools/performance/run.sh before
bash tools/performance/run.sh after
```

В локальном стенде используется отдельная SQLite-база только с публичным каталогом. Прогоны браузера проверяют ограничения клиента; производительность production PostgreSQL при массовых записях этими числами не заявляется. Реальные почта, SmartCaptcha, нагрузка регистраций и полевые камеры остаются отдельной приёмкой.

Технические ориентиры: [Chrome DevTools — измерение производительности](https://developer.chrome.com/docs/devtools/performance/reference), [Playwright в Docker](https://playwright.dev/docs/docker), [LCP и лабораторные измерения](https://web.dev/articles/optimize-lcp).
