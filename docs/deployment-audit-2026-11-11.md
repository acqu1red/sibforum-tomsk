Для этого алиаса настроен ограниченный Python ProxyCommand с привязкой только к физическому `en0`, адресу `179.252.220.7` и порту 22. Это позволило подключиться при работающем VPN; глобальные маршруты и VPN не менялись. Пароль root для входа не потребовался. Через официальный Docker APT-репозиторий установлены Docker Engine 29.9.3 и Compose 5.7.0. Настроена ротация Docker-журналов. Исходники загружены в `/opt/sibforum`; новые случайные секреты находятся только в `/etc/sibforum/production.env`, права 600.

В новой PostgreSQL применены все миграции, импортированы 171 объект публичного каталога. `check --deploy --fail-level WARNING` завершился без замечаний. Проверены реальные HTTPS-запросы с обычным DNS и проверкой цепочки сертификата: главная, промтур, конкурс, юридические страницы, ESG, CSS/JS, health и каталоги — 200; публичная админка и staff API — 404; admin login — 200, noindex и robots присутствуют. Через VPN один из запросов завершился таймаутом TLS; все проверки повторены через физический `en0` и прошли.

Тестовое продление Certbot (`renew --dry-run --no-random-sleep-on-renew`) прошло успешно для обоих доменов. Вход созданного администратора проверен по HTTPS: пароль принят, доступ перенаправлен на обязательную настройку TOTP; тестовая сессия завершена. В Chrome главная загружена, ошибок JavaScript нет.

Контейнеры backend, DB, Nginx, worker и backup запущены; база и API наружу отдельными портами не опубликованы.

## Найденные проблемы и изменения

1. **Главная и страницы в production возвращали бы 404.** Nginx направлял всё в Django, где нет маршрутов HTML-сайта. Добавлена раздача `site/` из Nginx, API направляется в Django. Файлы frontend не нужно копировать в backend-образ.
2. **Первый выпуск HTTPS не имел рабочего порядка запуска.** Nginx требовал ещё не существующий сертификат, Certbot в standalone-контейнере не публиковал порт. Добавлен HTTP bootstrap и общий ACME webroot. Продление работает при запущенном Nginx; добавлены systemd service/timer и reload после renew.
3. **Worker и backup могли стартовать до миграций.** Теперь они ждут готовности backend через healthcheck, который проверяет БД.
4. **В backend-образ мог попасть профиль Chrome.** В каталоге есть `.chrome-contest-review`, но исключался только `.chrome-review`. Исправлен `.dockerignore`: исключаются все `.chrome*`, секретные env и ключи. Контекст новой сборки составил около 174 КБ вместо передачи профиля браузера.
5. **Canonical, Open Graph URL и JSON-LD указывали на другой домен.** Основная страница переведена на `sibforum-tomsk.ru`; ссылки на существующие архивные сайты сохранены.
6. **ESG при отсутствии legacy API переходил к демонстрационной регистрации в localStorage.** Production возвращает 503 для старых страниц регистрации и личного кабинета; каталог ESG остаётся доступным. Legacy API не публикуется.
7. **Почта и капча пока не настроены.** Добавлен `PUBLIC_SUBMISSIONS_ENABLED=0` по умолчанию. Отправка и подтверждение заявок/бюллетеней закрываются на обоих доменах. Управляющий скрипт не открывает формы без SMTP и обоих ключей SmartCaptcha.
8. **Личные токены могли попадать в access log.** Формат журнала Nginx исключает query string и Referer. Личные ссылки не должны сохраняться в логах как bearer token.
9. **Не было команд безопасного обновления.** `deploy/upload.sh` передаёт только исходники; `deploy/production.sh` реализует check/bootstrap/https/update/renew. Обновление делает backup и заново запускает Nginx с актуальным шаблоном и адресом upstream. База и media не удаляются.
10. **Документация восстановления передавала RESTORE_CONFIRM только локальному процессу Compose.** Исправлено на `exec -e RESTORE_CONFIRM=1`, переменная попадает в контейнер.
11. **Ошибки SmartCaptcha ломали API голосования.** Общая проверка выбрасывала `RegistrationError`, а API конкурса обрабатывал только `VotingError`. Включение капчи превращало отсутствующий/неверный токен и сетевую ошибку в HTTP 500. Добавлено преобразование исключения с сохранением кода и статуса. Три новых регрессионных теста проверяют реальные ответы API: 422 для отсутствующего и отклонённого токена, 503 при недоступности сервиса, без создания бюллетеня.

12. **Витрина ошибочно писала «Регистрация открыта» при закрытых формах.** Nginx публикует текущий `PUBLIC_SUBMISSIONS_ENABLED` в `/deployment-config.json` без кеширования. Витрина показывает временную недоступность; промтур скрывает форму и отключает запись на маршруты; конкурс показывает закрытое голосование, сохраняя просмотр номинаций. При переключении флага интерфейс обновляется вместе с серверным ограничением.

## Данные

Старая локальная БД Docker не соответствует актуальному коду: при чтении нового каталога отсутствует таблица `forums_speaker`. У существующего worker bind mount указывает на прежний путь `/Users/headliner/Desktop/tpp_site/backend`, а текущий проект находится в Documents. Эти контейнеры и данные не изменялись.

Для проверки создана отдельная новая БД. В неё применены миграции, выполнено локальное наполнение программы и импорт исходного DOCX номинаций. Подготовлен `deploy/catalog.json`: 171 объект публичного каталога, без пользователей, участников, заявок, голосов, писем и TOTP. Импорт в новую production-БД выполняется отдельно один раз; обычное обновление не перезаписывает контент.

Программа содержит 19 событий, 6 маршрутов, 19 предприятий, 13 спикеров. Конкурс содержит 8 номинаций и 79 кандидатов. Рабочие лоты биржи и адреса кураторов отсутствуют. Несоответствие исходного PDF итоговой программы и редакции DOCX уже описано в `frontend-acceptance.md`; эта проверка его не разрешает.

## Что осталось перед открытием заявок и голосования

- Дополнительные учётные записи создаёт руководитель в панели. TOTP можно включить позднее через `ADMIN_TOTP_REQUIRED=1`.
- Подключить реальную отправку кодов и SmartCaptcha, проверить доставку писем и весь пользовательский цикл, затем открыть формы.
- Проверить актуальность программы, лоты и адреса кураторов. Текущие юридические тексты отмечены в проекте как требующие утверждения организатором.
- Настроить копирование backup за пределы VPS: первая внешняя копия уже сохранена на Mac, регулярное копирование ещё не подключено. Нагрузку, реальную доставку писем, камеры чек-ина и восстановление production-данных после размещения ещё не проверяли.

Git-репозитория в предоставленной папке нет. Для отката следует сохранять предыдущий образ, копию исходников и backup; откат только по Git commit сейчас невозможен. Полная последовательность команд находится в `docs/production-runbook.md`.
