# Повторное письмо и билет участника — 16 ноября 2026

Владелец подтвердил скриншотом получение всех восьми тестовых писем во «Входящих» Яндекса, включая два комплекта PDF/QR. Тестовая отправка выполнялась штатными шаблонами и почтовым backend в транзакции PostgreSQL READ ONLY, без создания заявок, билетов или записей очереди в рабочей БД.

## Возможности панели

В таблицах участников и заявок сразу после имени появился столбец «Письмо и билет». Кнопка повторной отправки использует POST с CSRF, проверяет право изменения заявок и ставит одно письмо в штатную очередь. Для подтверждённой регистрации повторно формируется актуальное содержание заявки и подписанная личная ссылка, которая не отзывает прежнюю. PDF/QR прикладываются штатным обработчиком при наличии действующего билета.

Если почта ещё не подтверждена, обновляются код, срок и счётчик попыток существующего незавершённого подтверждения. Сохранённый выбор и данные участника остаются прежними. Устаревшие ожидающие письма с кодом отменяются. При отсутствии незавершённой заявки панель предлагает участнику заполнить форму. Регистрация не подтверждается администратором автоматически.

Идентификатор запроса защищает от повторной обработки после двойного клика или сбоя соединения. Блокировка существующей заявки и минутный интервал защищают от параллельных повторов. Действие фиксируется в журнале Django admin без кода или личного токена в тексте истории.

Страница «QR / билет» показывает действующий билет, кнопки скачивания PNG/PDF и передачи PNG через Web Share API. Файл подготавливается до нажатия, чтобы сохранить пользовательский жест в мобильном браузере. При отсутствии API используется скачивание с пояснением. У пользователя без прав нет доступа к файлам; отозванный билет и неподтверждённая регистрация не выдают QR. Публичная ссылка для изменения заявки через этот механизм не раскрывается. Скачивание не меняет статус билета или регистрации, ответы помечены `no-store`.

## Проверки

90 автоматических тестов прошли. Восемь новых сценариев покрывают актуальное письмо с настоящими PDF/PNG, сохранность прежней личной ссылки и количества бизнес-записей, новый код без создания повторной заявки, защиту от двойного запроса и частых повторов, права, CSRF, запрет изменения через GET, скачивание только действующего билета и наличие команд в списках/карточках. Миграций не требуется.

В Chrome DevTools на локальной копии проверены обе таблицы, отправка для подтверждённой и неподтверждённой заявок, отображение очереди писем, PNG и PDF с правильными заголовками, отсутствие QR до выдачи билета, адаптивность на 390 px. Вызов Web Share API проверен подменой системного обработчика: он получил настоящий PNG-файл; реальное сообщение в мессенджер не отправлялось. Проверена и ветка скачивания без Web Share. Ошибок JavaScript не обнаружено.

Рабочие заявки в ходе проверки не отправлялись повторно, не одобрялись и не менялись. Перед обновлением сохранены отдельные dump PostgreSQL и архив исходников, затем выполнено штатное обновление приложения. Резервные копии и материалы тестирования остаются вне Git.
