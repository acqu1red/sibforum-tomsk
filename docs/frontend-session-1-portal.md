# Frontend-сессия 1: витрина форумов и таймер ближайшего

Сначала прочитать `docs/frontend-sessions-integration.md` и выполнять его ограничения.

## Цель

Обновить основную витрину `siberianforum.ru`: ближайшим сделать V форум по промышленному туризму, показать его актуальную программу и таймер, сохранить архив и обеспечить переходы на сайт промтура и конкурс.

**Выполнять все этапы сразу, без остановок для согласования и без `AskUserQuestion`. После каждого этапа переходить к следующему, пока не будут выполнены проверки.**

## Разрешённые файлы

- `site/index.html`
- `site/js/showcase.js`
- `site/js/portal-data.js`
- `site/js/hero.js`
- только портальные блоки `site/css/style.css`
- новые изображения в отдельной папке `site/img/portal/`

Не изменять `site/promtour/**`, `backend/**`, `server/**`, Docker-файлы и `ROADMAP_REWORK.md`.

## Этап 0. Аудит текущего поведения и диалога

1. Прочитать текущие `site/index.html`, `site/js/showcase.js`, `site/js/portal-data.js`, `site/js/hero.js` и портальные CSS.
2. Самостоятельно прочитать весь `dialog2/dialog2.md`. Составить матрицу «реплика/требование → элемент витрины → файл → проверка» и использовать её при финальной приёмке.
3. Принять текущий дизайн за обязательную основу: сохранить шапку, кнопки, карточки, сетку, цвета, Onest/Montserrat, скругления, тени и общий визуальный язык. Не придумывать новый стиль и не переписывать витрину под другой референс.
4. Запустить текущие контейнеры, если не запущены:

   ```bash
   docker compose -f docker-compose.backend.yml up -d
   docker compose -f docker-compose.yml up -d --build
   ```

5. Открыть `http://localhost:8095/` и зафиксировать, что сейчас ближайшим ошибочно является ESG с устаревшей датой, а таймер имеет демонстрационную логику.
6. Изучить источники по приоритету из общего контракта. Не использовать старые ESG-тексты для нового hero.
7. Проверить, как отображаются шесть маршрутов на сайте `/promtour/`, но не менять этот сайт самостоятельно.

Результат этапа: список текущих компонентов, которые сохраняются, матрица требований диалога и список данных, которые заменяются актуальными.

## Этап 1. Карта актуального контента

В `site/js/portal-data.js` сформировать данные ближайшего форума:

- серия: `promtour`;
- номер: `V`;
- название: `V Сибирский форум по промышленному туризму #ПРОМОТУРТОМСК–2026`;
- даты: 23–24 ноября 2026;
- город: Томск;
- старт для таймера: `2026-11-23T09:00:00+07:00`;
- основная площадка делового дня: ОЭЗ ТВТ «Томск», пр. Развития, 3;
- сайт: `/promtour/`;
- программа: `/promtour/#program`;
- регистрация: `/promtour/#registration`;
- конкурс: отдельный CTA на страницу конкурса/голосования в текущем сайте промтура.

Контент первого экрана брать из подтверждённых материалов промтура и спикеров/номинаций. Не копировать описание ESG. PDF с именем итоговой программы 09.11 при проверке оказался другим форумом РЦИС на 11.11: не переносить его содержимое. См. `docs/frontend-acceptance.md`.

В архиве сохранить реальные прошлые форумы. Не представлять прошлые форумы как ближайшие и не создавать фиктивные карточки.

## Этап 2. Витрина и навигация

1. Обновить hero ближайшего форума без потери читаемости на 360 px.
2. Оставить понятные действия:
   - «Перейти на сайт форума»;
   - «Программа»;
   - «Зарегистрироваться»;
   - отдельный заметный «Конкурс “Индустриальный код”» / «Голосовать» на `/contest/`, а не статическую карточку без отправки.
3. Сохранить и при необходимости улучшить фильтры архива по серии и году.
4. Обновить настольное и мобильное меню: форумы, промтур, конкурс, организатор, контакты.
5. Не добавлять второй несовместимый стиль кнопок, новых библиотек или рекламных баннеров.
6. Сохранить блоки организатора, контактов и футер без выдуманных ссылок.

Результат этапа: готовая витрина с актуальным ближайшим форумом и рабочими переходами.

## Этап 3. Таймер и состояния

Переработать `site/js/hero.js` только для портала:

1. Считать время до `2026-11-23T09:00:00+07:00`, независимо от часового пояса устройства.
2. Не использовать условную дату и не подставлять 23 дня, если целевая дата прошла.
3. Предусмотреть:
   - анонс до открытия регистрации, если дата открытия задана;
   - регистрация открыта до старта;
   - форум идёт сейчас 23–24 ноября;
   - форум завершён после 24 ноября с итогами/материалами.
4. Не показывать `00:00:00:00` после окончания. Во время форума вместо таймера показывать текущий день/мероприятие по актуальной программе, если она доступна.
5. Демонстрационные переключатели A–D оставить только для разработки и убрать из production-видимости.
6. Не ломать таймер сайта `esg2026`: портальная логика не должна зависеть от ESG-контента.

Результат этапа: таймер работает по реальным датам и корректно переключает состояния.

## Этап 4. Проверка и исправления

Обязательно, без остановки после визуального осмотра:

1. `node --check site/js/showcase.js` и `node --check site/js/portal-data.js`, `node --check site/js/hero.js`.
2. Проверить HTTP:
   - `/` возвращает 200;
   - `/promtour/` возвращает 200;
   - `/api/v1/forums/promtour/program/` возвращает 200 и используется существующим сайтом;
   - `/api/ping` продолжает работать.
3. В Chrome на 360, 768, 1280 и 1920 px проверить:
   - отсутствие горизонтального overflow;
   - читаемый hero и таймер;
   - отсутствие наползающих карточек;
   - работу меню и CTA.
4. Пройти путь: витрина → сайт форума → программа → регистрация.
5. Проверить клавиатурную навигацию и видимый focus.
6. Исправить найденные ошибки и повторить проверку, не ожидая отдельного указания.

Временные Chrome-профили, скриншоты и тестовые state-файлы удалить после просмотра.

## Критерии готовности сессии

- Ближайший форум — промтур 23–24.11.2026, а не ESG.
- Таймер ведёт на 23.11.2026 09:00 +07 и не демонстрирует условные числа.
- Есть отдельные переходы на сайт форума, программу, регистрацию и конкурс.
- Нет ссылки на четыре маршрута: пользователь видит шесть актуальных маршрутов на сайте форума.
- Архив и старые форумы не сломаны.
- Нет Lorem ipsum, ESG-текстов в hero, заглушек и пустых ссылок.
- Текущий дизайн витрины сохранён как основа, а не заменён новым стилем.
- Матрица `dialog2/dialog2.md` заполнена: каждое относящееся к витрине требование сопоставлено с реализацией и проверкой.
- Все проверки выполнены, ошибки исправлены, временные файлы удалены.

Финальный ответ сессии: перечислить изменённые файлы, результаты HTTP/Chrome-проверок и расхождения источников, которые требуют ручной контентной сверки. Не останавливаться на рекомендациях — требуется готовый код.
