# Сайт «Сибирский форум»

Проект содержит витрину форумов, новый сайт промтура 2026 и сохранённый ESG-прототип. Промтур работает через Django/PostgreSQL; старый ESG-шаблон и его демонстрационные endpoints сохранены отдельно.

## Запуск

- `start-site.bat` запускает локальный сервер и открывает витрину: http://localhost:8095/.
- Для полного контура с регистрацией, письмами и админкой выполните из корня:

  ```bash
  docker compose -f docker-compose.backend.yml up -d --build
  docker compose -f docker-compose.yml up -d --build
  ```

- `start-site-docker.bat` запускает только витринный Docker-контейнер; `stop-site-docker.bat` останавливает его.
- Если Python не установлен, `start-site.bat` также использует Docker.
- Двойной клик по `index.html` оставляет старую ESG-регистрацию в браузерном демо-режиме. Этот режим не используется для нового промтура и его персональных данных.

Основные адреса:

- витрина: http://localhost:8095/;
- промтур: http://localhost:8095/promtour/;
- конкурс: http://localhost:8095/contest/;
- админка: http://admin.localhost:8100/admin/;
- выгрузки: http://admin.localhost:8100/admin/exports/;
- сканер прибытия: http://admin.localhost:8100/admin/check-in/;
- Mailpit: http://localhost:8026/;
- production-like API: http://localhost:8101/api/v1/health/.

Подробности backend: `backend/README.md`. Итоговая проверка: `docs/frontend-acceptance.md`.

На основном домене `/admin/` и staff API возвращают 404. Для администраторов используется отдельный хост `admin.sibforum-tomsk.ru` (локально `admin.localhost`), пароль и TOTP. `sitemap.xml` для admin-хоста отсутствует, индексация запрещена через `robots.txt` и `X-Robots-Tag`. Это не замена авторизации. Google Authenticator совместим с существующим TOTP; OAuth и IP-whitelist не нужны.

## Витрина

- Ближайший форум — V Сибирский форум по промышленному туризму #ПРОМОТУРТОМСК–2026, 23–24 ноября 2026, Томск.
- Таймер ведёт на 23.11.2026 09:00 UTC+7 и автоматически переключает анонс, регистрацию, проведение и завершение. После окончания нули не показываются.
- Во время форума показывается текущее событие из backend.
- Есть отдельные переходы на сайт, программу, регистрацию и конкурс «Индустриальный код».
- Сохранены фильтры архива по сериям и годам, организатор, контакты и действующий ESG.
- Данные: `js/portal-data.js`; отображение: `js/showcase.js`; состояния: `js/hero.js`.

## Промтур

- В публичной программе 19 событий в API, включая шесть маршрутов с 19 предприятиями. На странице маршруты показаны отдельными карточками.
- Программа, предприятия, спикеры, роли и фотографии редактируются через Django Admin и загружаются из `/api/v1/forums/promtour/program/`.
- Статический JS содержит только начальное представление до загрузки API; изменения в админке попадают на публичную страницу после обновления.
- Маршрут стоит 2500 ₽, оплата обсуждается с куратором после заявки. Онлайн-оплаты нет. Можно выбрать только один маршрут.
- Обычные события подтверждаются после email; маршруты и биржа проходят ручную модерацию.
- Биржа доступна для записи после публикации лотов и https-ссылок на технические материалы. Пустые демонстрационные ссылки не выводятся.
- Специфическая страница мастер-класса на Leader ID пока не предоставлена, поэтому сайт сообщает об этом без подмены ссылки.
- Обязательные поля анкеты: фамилия, имя, отчество, email, телефон, организация, должность, категория. Город, источник и комментарий необязательны. ИНН и формат участия отсутствуют.

Для локального наполнения при `DEBUG=1`:

```bash
docker compose -f docker-compose.backend.yml exec backend python manage.py seed_promtour_dev
```

Seed идемпотентен и сохраняет идентификаторы существующих событий. Он не предназначен для production.

**Источники:** PDF с именем итоговой программы 09.11 при визуальной проверке оказался другим форумом РЦИС на 11.11. Поэтому фактическая программа взята из DOCX 02.11, спикеры — 06.11, маршруты и номинации — из отдельных DOCX. Расхождение требует контентного решения заказчика.

## Голосование, билет и админка

- Конкурс содержит 8 номинаций и 79 кандидатов из `контент/Номинации  03.11.2026.docx`.
- На странице форума показаны только номинации и переход к голосованию. Полный бюллетень находится на `/contest/`; обе страницы используют один backend-каталог.
- Можно пропускать незнакомые номинации; лимиты кандидатов проверяются и в браузере, и на сервере.
- Один подтверждённый email = один бюллетень. Публичные итоги скрыты до отдельной публикации.
- Личная страница `/promtour/?t=...` содержит QR и PDF. QR ведёт только на защищённый чек-ин, а не на редактирование заявки.
- В админке есть модерация, отмена и отдельная форма перевода на другой маршрут, история решений и письма участнику.
- Доступ сотрудников защищён индивидуальным логином и TOTP. Три рабочие учётные записи создаются отдельно, общий пароль не используется.
- Выгрузки участников и голосования доступны в CSV/XLSX с фильтрами и агрегированной статистикой, без внешней CRM.

## Backup

Сервис `backup` сохраняет базу и media (фотографии спикеров) в комплекты JSON + TAR.GZ. Хранятся 14 комплектов. Восстановление требует `RESTORE_CONFIRM=1` и отдельной проверки на другой БД. Инструкция: `docs/production-runbook.md`.

```text
site/
  index.html            витрина всех форумов
  promtour/             сайт ближайшего промтура и конкурс
  esg2026/              сохранённый ESG-прототип

```

## Старый ESG-прототип

ESG сохраняет прежние страницы `index.html`, `program.html`, `register.html`, `my.html` и демонстрационную модель событий. Не переносите его модель «время × трек» в новый промтур.

Старые endpoints `/api/register`, `/api/confirm`, `/api/registration`, `/api/seats` остаются только для этого прототипа. Legacy `/api/export.csv` требует заголовок `X-Export-Token` со значением `LEGACY_EXPORT_TOKEN`; без него возвращает 401. Основные выгрузки находятся в защищённой админке с TOTP.

Старые JSON-файлы в `server/data/` содержат демонстрационные заявки и имитацию CRM-очереди; внешняя CRM в новом контуре не используется. Эти файлы нельзя публиковать или пересылать.

Условные тексты ESG-программы, требования экскурсий и демонстрационные состояния остаются только в старом шаблоне. Его таймер можно переключать параметром `?state=A|B|C|D`; витрина промтура переключается по реальным датам.

Документы в `site/legal/` и тексты согласий требуют утверждения заказчиком перед production. Настоящие DNS, SMTP и SmartCaptcha локально не считаются проверенными production-сервисами.
